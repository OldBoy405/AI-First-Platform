# CR 流程降本提效：需求来源文档

**文档性质** CR 需求来源（自包含，可直接用于 CR 注册与 PRD 编写，无需并读任何其他文档）
**日期** 2026-09-16
**提出人** Ray
**实测口径** 643 个 pi 会话的工具结果合计 **49.7M tokens**（o200k 编码；扫描区间 2026-08-18 ~ 2026-09-16，共 672 个会话文件）

---

## 1. 一句话需求

CR 流程当前每个 CR 平均消耗 **17 个会话**、工具结果 token 规模达 **49.7M / 643 会话**，且 59% 的消耗来自 shell 输出、43% 的文件读取来自每会话重复加载的规范文档。本 CR 在**不改动任何 CR 流程语义**的前提下，通过「受控 shell 护栏 + 文档分层 + 跨会话交接 + 事实页生成」四类手段，降低 token 消耗并减少会话数与返工轮次。

---

## 2. 术语定义（本文自包含）

| 术语 | 定义 |
|---|---|
| **会话** | 一次 agent 运行的完整对话记录（一个 pi session 文件） |
| **工具结果 token** | agent 每次工具调用返回内容的 token 数（o200k 编码），不含模型输出与历史重送 |
| **整读** | 一次调用读取文件全部内容（无 offset/limit、无行数截断） |
| **切片读** | 一次调用只读取文件的一段（带 offset/limit 或管道截断） |
| **加载型读取** | 整读比例高的读取行为，agent 是在「装载规范」而非「查找答案」 |
| **检索型读取** | 整读比例接近 0 的读取行为，agent 是在「查某个事实」 |
| **bootstrap 成本** | 每个会话开工前为建立上下文而重复读取规范文档的 token 消耗 |
| **CR 工件** | CR 目录下的流程产出物（`prd.md` / `sdd.md` / `plan.md` / `tasks/*.md` / `test-report.md` 等） |
| **受控 shell** | 本环境中 agent 执行 shell 与 git 的白名单网关层 |
| **护栏指标** | 用于判断「降本是否伤害了流程质量」的反向指标 |

## 3. 背景与实测事实

### 3.1 按工具分布（合计 49.7M）

| 工具 | tokens | 占比 |
|---|---:|---:|
| shell（powershell + bash） | 29.5M | **59%** |
| read 工具 | 18.7M | 38% |
| grep / find | 1.1M | 2% |
| 其余 | <0.5M | <1% |

### 3.2 shell 输出细分（29.5M）

| 类别 | tokens | 占比 | 调用特征 |
|---|---:|---:|---|
| 搜索（rg / grep / Select-String） | 10.97M | 37% | 8663 次；**83% 已带某种截断，仍烧掉 7.9M** |
| 其它（复合命令 / 管道） | 7.26M | 25% | — |
| 文件内容打印（Get-Content / cat / sed） | 5.98M | 20% | 6356 次；72% 已带截断 |
| 执行（测试 / 构建 / 脚本） | 2.33M | 8% | **其中 crctl 自身命令输出 1.24M，占本类 53%** |
| 目录列举（-Recurse / find / ls） | 2.32M | 8% | — |
| git | 0.57M | 2% | — |

**关键观察**：单次 ≥30k 的调用几乎不存在，成本由**大量中小调用**堆积而成；65% 的调用已经在做截断。问题不是「要不要截断」，而是**检索次数多、目标发散**——没有好地图，就用广搜代替定位。

### 3.3 文件读取分族（tools 包内容读合计 13.60M）

| 族 | tokens | 占比 | 整读比例 | 读取性质 |
|---|---:|---:|---:|---|
| **A. crctl 源码**（`crctl.mjs` 1.85M / 470 会话；`lib/workspace-transactions.mjs` 1.39M / 129 会话；`durable-tx.mjs`） | 3.34M | 24.6% | **0%** | 纯检索型 |
| **B. SKILL.md 族**（49 个文件） | 2.79M | 20.5% | **35%** | 加载型 |
| **C. 流程元数据族**（`pipeline-templates/*` 1.20M / 93 会话、`agent-skill-matrix.yml` 355k / 175 会话、`gates.json` 185k / 107 会话、`skills/_index.yml` 182k / 61 会话、`controlled-shell/rules.json` 137 会话） | 2.68M | 19.7% | **36%** | 加载型 |
| **D. 指引类 md**（`CUSTOM.md` 1.00M / 86 会话、`AGENTS.md` 0.97M / 209 会话、`README` 0.50M / 173 会话、`architecture.md` 0.37M / 85 会话、`claude.md` 0.28M / 72 会话） | ~3.12M | ~23% | 高 | 加载型 |
| **E. 测试 / 夹具族** | 0.84M | 6.2% | 22% | 检索型，受众窄 |

B/C/D 三族合计约 **8.6M ≈ tools 读取的 63%**，且全部是**每会话重复**发生的 bootstrap 成本。

SKILL.md 族内最大五项：`develop/review-tech-design` 365k、`shared/crctl` 344k、`develop/write-tech-design` 335k、`develop/review-dev-plan` 319k、`develop/review-code` 240k。

### 3.4 CR 工件读取（tools 包之外）

`sdd.md` 2.58M / 412 次 ｜ `prd.md` 1.37M / 256 次 ｜ `plan.md` 0.50M ｜ `test-report.md` 0.13M。
说明：后续每个开发 / 测试 / 评审会话都在重读同一份大文档。

### 3.5 会话结构

- 610 个带 CR 号的会话 / 36 个 CR ≈ **17 会话/CR**（中位 8，P75 12，P90 56，max 124）
- 极端值：某 CR 124 会话 / 8.05M；另两例 56 会话 / 5.97M、57 会话 / 4.82M
- 单会话最贵 1.15M（1449 次工具调用）

同一份上下文在一个 CR 内被重建约 17 次，所有 bootstrap 成本都要乘以这个系数。

### 3.6 已排除的假设（实测否证）

- **不是运行时读取问题**：crctl 与事务层运行时解析的文件全部 ≤4k tokens，无优化空间；13.6M 几乎全部来自 agent 主动取证。
- **不是"有几个大文件没治"**：有 6 个大文件在 672 个会话中零命中，治它们收益为 0。

## 4. 根因分析

### R-1 两种读取需要两种药，现状只用了一种思路

| 读取性质 | 判据 | 有效手段 | 无效手段 |
|---|---|---|---|
| 检索型 | 整读比例 ≈ 0（如 crctl 源码 0%） | 建索引 / 生成事实页 | 把文件改小（agent 本来就不整读） |
| 加载型 | 整读比例 ≥ 35%（B/C/D 三族） | **把文件本身分层改小** | 建索引（它不是在查，是在装） |

加载型占 tools 读取 63%，是最大且最易被误诊的一块。

### R-2 靠提示词约束行为，跨模型不稳定

检索纪律（先定位后读取、限制输出）若只写进 SKILL.md，其效果完全依赖模型的提示词遵从度。**更换 LLM 即发生衰减**，且规范本身还要占用每会话的 bootstrap token。凡能落到工具默认值 / 网关校验的，就不应落在提示词。

### R-3 会话数是乘数，未被治理

17 会话/CR 意味着上下文被重建 17 次。没有标准交接产物时，每个新会话都从零取证——这同时是 token 成本和**效率损失**（返工、重复结论、决策漂移）。

### R-4 成本口径未与真实账单对齐

49.7M 是「工具结果文本量」，不是账单 token。agent 每轮会重送历史上下文，真实 input token 远大于此，又被 prompt cache 部分抵消。缺少换算系数时，任何节省量都无法翻译成金额，优化优先级也无法用成本排序。

## 5. 目标与非目标

### 5.1 目标（按重要性）

- **G-1 效率**：降低会话数/CR 与返工轮次
- **G-2 成本**：降低单位 CR 的工具结果 token
- **G-3 可持续**：优化手段不依赖特定模型的提示词遵从度

### 5.2 非目标

- 不追求总 token 绝对值下降（工作量本身会波动，指标必须归一化）
- 不改变 CR 流程的阶段、门禁判定、审批与事务语义
- 不以牺牲取证充分性换取 token 节省

---

## 6. 硬约束与红线

| 编号 | 约束 | 说明 |
|---|---|---|
| **X-1** | **流程语义零改动** | 不修改阶段机、门禁 passCondition、审批链、事务/worktree 行为 |
| **X-2** | **不复刻判定逻辑** | 任何摘要页/索引只提供「定位」（对象 → 文件:行），不得复制 passCondition 或门禁判定逻辑，避免出现第二处真相 |
| **X-3** | **生成物必须可验证且不会过期** | 每条生成的事实带 `文件:行` 出处；生成物与源码一致性由 CI 校验，不一致即失败 |
| **X-4** | **必须有逃生阀** | 任何截断/拒绝都要给出「如何合法取得全量」的提示，并允许在取证不足时升级为全读（会话内记录一行原因） |
| **X-5** | **护栏指标不得恶化** | 门禁一次通过率不下降、返工循环数不上升、评审阶段发现缺陷数不下降；任一恶化即回滚对应措施 |
| **X-6** | **受控写路径** | 涉及 `specs/`、`delivery/`、写回模板的改动需人工确认并按流程走，不由 agent 直接改 |

**X-5 是「不影响 CR 流程」的可证伪定义**：为省 token 而少取证、把缺陷漏到下游，成本远高于 token 本身。

### 7.2 scope_out（明确不做，附理由）

| 项 | 理由 |
|---|---|
| **测试与夹具族索引** | 该族合计 0.84M（占 tools 读取 6.2%），且仅在「改 crctl 的 CR」中被读，全部为切片读（单次 ≤8.3k），受众窄、性价比最低。**本 CR 明确不做** |

## 8. 功能需求

> 每条含：现状事实 → 要求 → 落地面 → 验收要点。编号供 PRD/SDD 追溯使用。

### 分组 I：受控层护栏（不依赖模型遵从，风险最低，优先落地）

**FR-1 受控 shell 检索与输出护栏**
- 现状：搜索类 10.97M（8663 次）、目录列举 2.32M、文件打印 5.98M；83% 的搜索已带截断仍高消耗。
- 要求：
  1. 无过滤条件的全仓递归列举（无 `-Filter/-Include`、无路径限定）→ 拒绝执行，返回一行正确写法建议；
  2. 搜索类命令未指定命中上限时，自动施加上限；命中数超阈值时只返回文件列表并提示改用「先定位文件、再小窗取证」；
  3. 单次命令结果超阈值自动截断，附一行「已截断 ≈Nk tokens，缩小范围的具体写法」；
  4. 禁止大文件全文打印（如整文件 `Get-Content` / `cat` / `tr` 管道），提示改用带行号与区间的读取方式；
  5. 全部规则必须满足 X-4 逃生阀。
- 落地面：受控 shell 的规则配置与网关校验逻辑。
- 验收：违规命令被拒并给出可执行替代写法；合法命令零误伤；搜索类 token 占比下降。

**FR-2 crctl CLI 输出瘦身（仅呈现层）**
- 现状：crctl 自身命令输出 1.24M，占「执行类」2.33M 的 53%。
- 要求：列表类命令默认摘要输出（完整内容需显式 flag）；写操作默认只回 `id + status + 关键结果`；`--output json` 默认 compact；提供统一的「详情」开关。
- 落地面：crctl CLI 的输出格式层。
- 验收：同一批常用命令的输出 token 显著下降；**命令的退出码、语义、事务行为逐一不变**（X-1）。

### 分组 II：加载型文档分层（覆盖面最大）

**FR-3 SKILL.md 族分层**
- 现状：49 个文件合计 2.79M，整读比例 35%；最大五项 365k / 344k / 335k / 319k / 240k。
- 要求：每份拆为「必读核心 ≤2k tokens」+「按需附录」，核心内含指向附录的明确锚点；**内容不删除，只分层**。优先处理上述最大五项。
- 落地面：`skills/**/SKILL.md` 及其附录文件。
- 验收：核心部分 ≤2k；整读次数占比下降；对应阶段的护栏指标不恶化。

**FR-4 指引类 md 分层**
- 现状：`CUSTOM.md`（209KB，86 会话）、`AGENTS.md`（209 会话）、`README`、`architecture.md` 等合计约 3.12M，整读比例高。
- 要求：同 FR-3 手法，「核心 ≤10KB + 按需附录」；核心只保留每会话真正必读的约束。
- 落地面：各仓根目录指引文档。
- 验收：核心体积达标；每会话 bootstrap token 下降。

**FR-5 流程元数据定位摘要页**
- 现状：`pipeline-templates/*` 1.20M（93 会话）、`agent-skill-matrix.yml` 355k（175 会话）、`gates.json` 185k（107 会话）、`skills/_index.yml` 182k（61 会话），整读 36%。
- 要求：生成只读摘要页——流水线节点/门禁/产出物 → `文件:行` 定位；gates 与证据文件映射；注册面（agent-skill 矩阵、skill 索引）摘要。**严格只做定位，不复刻 passCondition**（X-2）。
- 落地面：生成器 + 生成物 + CI 校验（与 FR-9 共用机制）。
- 验收：元数据族整读次数下降；摘要页与源文件一致性由 CI 保证。

### 分组 III：流程结构（治会话乘数，效率收益最大）

**FR-6 跨会话交接卡**
- 现状：17 会话/CR（P90 56，max 124），上下文被重建约 17 次。
- 要求：定义固定模板（≤2k tokens），字段固定为：现状 / 关键决定 / 待办 / 涉及文件:行 / 已排除方案。作为每个会话收尾的固定产出；新会话读 1 份即可开工。
- 落地面：交接卡模板 + 会话收尾约定 + 存放位置约定。
- 验收：新会话首 N 次调用的 bootstrap token 下降；会话数/CR 中位数下降。

**FR-7 CR 工件分节锚点**
- 现状：`sdd.md` 2.58M / 412 次、`prd.md` 1.37M / 256 次被反复读取。
- 要求：PRD/SDD 顶部强制「节目录 + 稳定锚点」；任务卡给出「本任务相关节」指引，使会话按需读节而非全文扫描。
- 落地面：PRD/SDD 模板与任务卡模板（**受 X-6 约束，需人工确认并按流程自举**）。
- 验收：单次工件读取的平均 token 下降；工件完整性与评审可追溯性不变。

**FR-8 成本与护栏度量**
- 现状：仅有一次性人工统计，无常态口径；且未与真实账单对齐（R-4）。
- 要求：
  1. **账单对齐**：取 1–2 个已完成 CR 的 provider usage（input / cached input / output），与工具结果 token 求比值，得到放大系数 k；此后所有收益按 `k × 节省量` 折算；
  2. **常态指标**：`tokens/CR`、`会话数/CR`、`搜索类 token 占比`、`整读次数占比`、`单会话 bootstrap token`；
  3. **护栏指标**：门禁一次通过率、返工循环数、评审阶段发现缺陷数；
  4. **会话内轻提示**：单次工具结果超阈值时输出一行「本次输出 ≈Nk tokens」；
  5. **CR 收尾台账**：会话数、工具 token、读源码 token。
- 落地面：度量脚本 + 台账产出约定。
- 验收：基线快照可复跑；指标按归一化口径输出；不引入新的重型仪表盘。

### 分组 IV：检索型事实页（收益确定但需配 CI 兜底）

**FR-9 crctl 事实页与 CI 新鲜度校验**
- 现状：`crctl.mjs` 1.85M / 470 会话、`workspace-transactions.mjs` 1.39M / 129 会话，**整读比例 0%**——全部是「查某个事实」的切片读。
- 要求：
  1. 生成字段语义与错误码事实页（错误码 → 含义 → 可操作处置）；
  2. 生成 CLI 命令面索引（子命令 / flag → `crctl.mjs:行号`），消除 help 文本与 SKILL.md 的重复取证；
  3. **每条事实必带 `文件:行` 出处**（X-3），使 agent 一行即可验证，否则它不会信任生成物，仍会回头读源码，成本翻倍；
  4. **CI 新鲜度校验**：生成物与源码 hash 不一致即构建失败；
  5. 零新增运行时依赖，生成器不参与运行时路径。
- 落地面：生成器 + 生成物 + CI/pre-commit 挂点 + 相关 SKILL.md 的引用改写。
- 验收：字段语义/错误码类问题可在生成物内闭环（目标：典型取证模式由约 11.5k → 约 3.5k tokens）；源码改动后 CI 能拦住过期生成物。
- **前置状态说明**：本项需在 tools 仓派生 worktree 并提交生成物。该仓此前存在 git 对象库缺损导致 worktree 无法派生的问题，**已于 2026-09-11 修复并在本次复核中确认健康**（历史整树 diff 可正常遍历、`fsck` 除陈旧 reflog 条目外零错误、worktree 列表干净）。**因此本项无人工前置阻塞**；动手前按惯例复核一次三仓 healthy 即可。

## 9. 验收标准

| 编号 | 验收标准 | 判定方式 |
|---|---|---|
| **AC-1** | 受控层护栏生效：违规检索/列举/打印命令被拒或被封顶，且每次均返回可执行的替代写法 | 用一组违规命令与一组合法命令回归，合法命令零误伤 |
| **AC-2** | crctl 输出瘦身后，常用命令集输出 token 下降，且**退出码与行为逐一不变** | 同一命令集前后对比 + crctl 既有测试全绿（不得因本 CR 新增失败） |
| **AC-3** | SKILL.md 与指引类 md 的核心部分体积达标（SKILL.md 核心 ≤2k tokens；指引类核心 ≤10KB），内容零丢失 | 体积核算 + 原文覆盖核对（核心+附录 ⊇ 原内容） |
| **AC-4** | 元数据摘要页与 crctl 事实页的每条结论均带 `文件:行` 出处，且不含任何 passCondition/门禁判定逻辑的复制 | 生成物抽检 + 关键词扫描 |
| **AC-5** | CI 新鲜度校验可拦截过期生成物 | 故意改动源码而不重生成，CI 必须失败 |
| **AC-6** | 交接卡模板落地并被实际使用，新会话可仅凭交接卡开工 | 抽取若干新会话，检查其首轮取证是否已不再从零开始 |
| **AC-7** | 归一化指标改善：`搜索类 token 占比`、`整读次数占比`、`tokens/CR`、`会话数/CR` 相对基线下降 | 以本文 §3 数据为基线，按 §10 口径复测 |
| **AC-8** | **护栏指标不恶化**：门禁一次通过率、返工循环数、评审阶段发现缺陷数 | 前后对比；任一恶化即触发回滚（X-5） |
| **AC-9** | 放大系数 k 已测定，所有收益按 `k × 节省量` 报告 | 台账中可见 k 的来源与计算 |
| **AC-10** | 流程语义零改动 | 阶段机/门禁/审批/事务相关代码零 diff（呈现层除外） |

## 10. 度量口径与复测方法（自包含规范）

**基线**：本文 §3 全部数据，基线日 2026-09-16。

**数据源**：本机 pi 会话记录目录（`.multica/pi-sessions` 与 `.pi/agent/sessions`），扫描区间 2026-08-18 ~ 2026-09-16，672 个会话文件。

**统计方法（需可复现实现）**：
1. 遍历会话记录，取每次工具调用的**返回内容**，按 o200k 编码计 token；
2. 按工具类型归类（shell / read / grep / find / 其它）；shell 再按命令形态归类（搜索 / 打印 / 执行 / 目录列举 / git / 其它）；
3. 文件维度：从命令与参数中解析被读文件路径，区分「内容读」与「执行输出」；判定整读 vs 切片读（有无 offset/limit 或行数截断）；
4. CR 维度：从会话内容中提取 CR 号，聚合会话数与 token；输出中位/P75/P90/max；
5. 输出归一化指标：`tokens/CR`、`会话数/CR`、`搜索类 token 占比`、`整读次数占比`、`单会话 bootstrap token`。

**复测**：实施后按同一实现、同一口径，仅变更时间区间复测；**只比较归一化指标，不比较绝对总量**（工作量波动会污染绝对值）。

**账单对齐**：取 1–2 个完整 CR 的 provider usage 实际值，与同区间工具结果 token 求比值得到 k；所有收益以 `k × 节省量` 报告。

## 11. 实施分期与依赖

| 阶段 | 内容 | 依赖 | 风险 |

| **第 2 阶段** | FR-3、FR-4（先各选 3 个最大文件试点，验证护栏指标后铺开） | 人工确认改动范围 | 低-中 |

**排序依据**：先做「不依赖模型遵从、流程风险为零」的受控层，再做「覆盖面最大」的文档分层，再治会话乘数，最后做「需要 CI 兜底」的生成物。

## 12. 风险与回滚

| 风险 | 影响 | 缓解 | 回滚 |
|---|---|---|---|
| 生成物过期被 agent 当真 | **唯一可能影响 CR 正确性的风险** | X-3 + AC-5：出处行号 + CI hash 校验 | 校验失败即阻断；必要时下线生成物并恢复源码取证 |
| 护栏过严导致取证不足 | 缺陷漏到下游 | X-4 逃生阀 + X-5 护栏指标 | 放宽阈值或撤下对应规则 |
| 文档分层后核心遗漏关键约束 | 执行质量下降 | 试点先行（每类先 3 个文件）+ AC-3 内容覆盖核对 | 恢复原文件结构 |
| 摘要页与真相二元化 | 判定不一致 | X-2：只做定位不复刻逻辑 | 删除越界内容 |
| 呈现层改动误伤 crctl 行为 | 流程中断 | AC-2 + AC-10：既有测试全绿 + 语义零 diff | 回退输出层改动 |
| 指标改善但质量下降 | 假性收益 | X-5 三项护栏指标 | 按措施粒度逐项回滚 |
