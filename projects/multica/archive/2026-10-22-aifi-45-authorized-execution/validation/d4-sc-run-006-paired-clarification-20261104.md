## 1. 现行文本的问题

```yaml
- id: SC-RUN-006
  given: T拒绝新准入或查询故障；另有已花完最后名额的有效receipt、撤销revision及签名resume分支。
  then: SHALL 拒绝新的未准入修复但允许最后已准入修复的测试、独立验证和PASS交付，不能自算预算或伪装首次实施。
```

两个 `given` 被并成一句，导致两种相反的读法都能自洽：

- 读法 A（保守）：查询故障 = 无法核实当前授权 → 只许安全停止；
- 读法 B（原正例）：查询故障不影响最后已准入任务 → 必须允许验证与合法交付。

计划要求「须按故障范围和当前权威证据配对澄清，不得无条件删掉正例或推定允许发布」。所以不能只留 A，也不能只留 B。

## 2. 澄清的判据：按动作所需的权威分档

不按「故障名字」分支，按**该动作需要哪些权威可核实**分支：

| 动作 | 必需权威 | 任一必需权威不可核实 |
|---|---|---|
| 新增准入（第七次及以后） | T 裁决 + 当前 head/budget/stop | 拒绝（与故障类型无关） |
| 已准入任务的只读验证、测试执行、结果登记 | 本地 receipt + 原 reservation/attempt 绑定 | 允许（不产生外部效果）；结果须标真实状态 |
| 独立评审 / PASS 判定 | 同上 + 评审证据可核 | 允许；证据不足则不得判 PASS |
| 交付（push/merge/deploy 等新外部效果） | 上述 + 当前授权代次 + 撤销排序可核 | 拒绝，转安全停止与对账 |
| 安全停止、现场保全 | 无（不需要外部权威） | 允许 |

**关键**：预算刚好耗尽（第六次已是最后一次）**不是**撤销、也**不是**故障；它只关闭「新增准入」，不影响已有任务的合法交付。这一点必须在文本里显式写出，否则容易被读成「额度没了就停」。
