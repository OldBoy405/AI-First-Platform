# 用户采纳可信 verdict 方案方向

## 用户确认原文

用户在阅读答复后回复：**“采纳建议，继续”**。

确认对象是答复中直接展示的四条方向，而不是据链接推定用户审阅或批准了整个技术文档：

1. 沿用已有方案，由隔离的控制服务作出并签名裁决，平台独立核验；普通 AI 执行者不能伪造裁决。
2. 由系统管理员维护受保护的可信名单；执行者不能修改名单或接触签名私钥。
3. 允许执行与实际效果分开；入队只证明入队，远端发布需要可靠回执或对账。超时、结果不明时暂停核查，不能猜成失败并盲目重试。
4. 尽量沿用现有协议：先验证现有签名格式是否够用；不够时再提出兼容方案或新版本。

答复同时披露：2026-10-27 记录显示本机隔离当时不成立，本次没有复测，生产使用前需要新的隔离证据；真实密钥控制者及名单来源仍须落地前核实。配套研究与建议：`verdict-authority-source-research-20261030.md`、`verdict-authority-recommendation-20261030.md`。

## 确认边界

- 这是**设计方向的对话确认**，不表示现网、密钥或存量事实已查明；不表示确定了签名字段、协议版本、回执来源、部署方案或各项工作归属。
- 不代替两侧新 change 的 Gate2/Gate3，也不批准扩大已确认 proposal 的 non-goal 或改动源码、测试数据库和真实部署。两侧仍在 SPEC / thorough。
- 历史事故库及其容器、卷继续 HOLD；不得回读，也不得运行绑定旧库的 runner。原 AIFI-45 的真实性验证及 Gate3 不被替代。
- 按已采纳方向继续细化可验证设计和测试，仍需明确未决项；准备好完整设计后另行向用户展示并等待明确 Gate2 确认。用户选择的全自动长程不跨过上述限制。

## 后续对话：恢复修订方向与存量前提

用户回复节选：**“异常恢复的业务取舍：同意按这个方向准备修订方案。现有使用情况：是。启用全自动长程模式”**。

- “这个方向”是展示过的候选：远端目标已达成但本次尝试未获证明时，显示目标达成/本次待核，不重推，不自动继续下一受保护动作，可能需要人工核查。用户同意**准备修订方案**，不等于已批准改变已归档 SC-MG-015/016 或确认 Gate1/Gate2；具体差异和生效范围须走正式评审。
- 问题原文为“此功能已用于真实业务，或可能已有旧数据？”用户答“是”；不能据此分别断言已用于真实业务、已有旧数据两者都确定。按可能已有使用或存量并需保护在途工作的保守前提设计，不因此访问或迁移旧数据。
- 用户再次要求启用全自动长程。原 AIFI-45 两侧 CLI 当前仍报告 `normal`；可信 verdict 两侧仍为 SPEC。按 STDD 需在适用阶段展示具体授权清单并取得确认，才可如实登记预授权；不得把选择意向冒充已启用，更不跨 Gate、HOLD、真实 CR 审批或生产权限。
