# RUN-009 平台外评审待核切片：独立静态审阅

## 结论：BLOCK，未经批准不得实施

按两仓当前配置请求 strong `GBClaude/claude-opus-5-5:high`；无 backend 回执，actual unknown。审阅仅读文件，未访问数据库、容器、网络、环境、会话或真实 CR，未运行测试。审阅对象为改写前的 `run009-pending-review-slice-draft.md`；此前作者请求的模型不在配置档位，见 `stdd-tier-audit-20261030.md`。

## 主要发现

1. **既有拒收有任务失败后果。** `review-note` 在服务端被 `UNKNOWN_KIND` 拒绝后，daemon 的 ACK/collector/settle 失败链可能使 CR 绑定任务报告 `CR_EVENTS_SETTLE_FAILED`；同 UID 可写 outbox 的坏事件也可能触发。三次 dead-letter 计数在内存，重启会重置。不能只称“未接入”。如何处置须评估现有 CUSTOM #284 严格 settle 合同，不能未经批准绕过。
2. **运输认证不证明真人作者或内容原件。** daemon token 分支未清除客户端自带 `X-User-ID`；应依据服务端认证上下文而非自报头。真实 daemon 当前可用 PAT，且同 UID Agent 能访问其凭据/队列，不能将 PAT、spool 上的先到内容或自报 reviewer 当作真人背书；共享主体配额亦可能被耗尽。
3. **复用现有 `/cr-events` 不是已证明的安全兼容边界。** 旧入口没有同等 body 限额；旧 server 会返回事件级拒绝，不能简单区分不支持与坏材料。独立入口、人类直接上传是应比较的较小候选，但其人类认证能力仍须实证。
4. **CLI 本地回执不证明平台已接收。** 本地文件可被同 UID 进程伪造；服务器状态应通过经认证的服务端查询核实。
5. **变更可能超出 Gate2 补充。** 原 proposal 的新增能力、非目标和现有通知合同均须重新审视；人工上传、处理和保留可能需要新的 proposal/Gate1。未经批准不得更换 AIFI-45 测试入口或新增待核材料主动通知。
6. **原草案过度设计。** 逐件 spool、另存冲突正文、原始运输 JSON、持久重试计数、死信、墓碑、指派/CAS/升级等均非已确认需求；应先比较更简单候选，不预设实施。

草案随后原位收敛为候选和待决问题。独立复核指出初版收敛稿弱化了“未认证声称不取得任何阻塞资格”方向，修正后复核 **PASS：仅表示候选稿可交人决定**；不代表 Gate1/2/3 批准或授权实施。复核同时要求保留 #284 严格 settle 的冲突待决、PAT 限制、冲突审计容量及正确源码路径，均已纳入。最终稿仍须在实施前核对同一源码快照。既有 RUN-009、SC-RUN-009 及 AIFI-45 Gate3 要求均未关闭。
