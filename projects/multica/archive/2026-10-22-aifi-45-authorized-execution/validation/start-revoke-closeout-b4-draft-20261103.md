# AIFI-45 启动、撤销与收尾：D4 配对合同草案

> **候选，不是已批准协议或完成证据。** 本文细化 WP0 D4 的边界与待决窗口，不开放生产启动，不改变现行 canonical、资源 HOLD 或 Gate3 NO-GO；须在适用 B4 中与 T/M、daemon、原 TC 和 D1/D2 的身份及防回退方案配对。本文不提出新的业务预算裁决者。

## 现行要求与当前源码边界

- [SC-RUN-003/005/006/008](../canonical/specs/code/authorized-runner.yaml) 分别要求消费前不推进、恢复原根不重复消费、撤销时未启动任务停止而已运行仅有界安全收尾、切换/回退不双派不清历史。SC-RUN-006 的正例还要求最后已准入任务可测试、独立验证和 PASS 交付；不可把仅剩额度耗尽当成撤销。
- [design.md](../design.md) 要求入队和实际启动前重查当前 head；失联不能启动新准入或敏感动作。SC-RUN-006 同时以「T 拒绝新准入或查询故障」为给定并要求原任务 PASS 交付。**故障具体覆盖哪些权威、何时仍可执行交付中的新外部效果，现行文字与本草案的保守失联候选存在需澄清的边界**：不可只保留拒绝分支当作原正例，也不能在无法证明当前授权时自行推定可发布。逐动作、逐故障类型配对修订或解释后再执行；审查不能仅看本文表格。
- `multica/server/internal/daemon/daemon.go:8664–8687` 的 `StartTask` 是准备目录后的服务端 dispatched→running 状态转换；`:9657–9671` 才调用 `backend.Execute` 并在其返回成功后标记 runtime started。前者不能证明进程已启动；后者是本地观察，当前没有证明它在可恢复的受保护历史中与原 receipt 和授权排序绑定。
- `daemon.go:8765–8777` 对绑定端点的交付 challenge 在 defer 中调用 `recordDeliveredConsumption`；当前 `daemon.go:848–852` 的 `New()` 将该记录开关置为 true，`execution_consumption_client.go:10–17` 所称生产默认关闭的注释已过时；未核实际部署配置。记录已交付 proof 不证明 T 已提交业务消费，该 defer 既不是启动前许可，也不是实际启动事实。
- `server/pkg/agent/proc_windows.go:73–126` 的现有 Windows Job 归属失败会记录警告并继续恢复执行；`proc_other.go:16–41` 的非 Windows 处理使用进程组及普通 `cmd.Start`。二者各有运行时用途，**均未证明**隔离、可靠阻断越权效果、全部后代受控或崩溃后不存在未观察执行。不能把 Job/process-group 存在、PID 或 running 字段当可信启动/安全停止证明。

以上仅是静态代码观察；没有运行进程、权限、网络或 DB 探针，也不能排除动态或外部入口。

## 候选事实和排序

1. **原请求与原根**：使用 T 已提交且经 M 核验的原 receipt、lineage/作用域、持久逻辑根及原派发映射；重放查询不得再消费或授予第二次启动。拟受保护 launch identity 必须绑定这些不可变事实、精确任务/claim generation、daemon 身份、执行版本和当前授权代次；字段与序列化尚待 D1/D2 决定。
2. **启动许可不是启动**：许可只能表示某一请求在某一受保护排序点可尝试首次启动；它本身不代表 OS 已创建进程，也不能保证后面仍未撤销。服务端的 `running`、T receipt、proof 已交付、内存标记及来自 Agent 的自报均不能替代受保护的实际启动证据。
3. **启动与撤销需要共同、实际执行的 fence**：原规范要求实际启动前重查；仅把许可和 revoke 写入同一 DB 行，不足以阻止许可先提交、revoke 后提交、旧许可再触发 OS spawn。必须说明谁持有权威及其不可绕过的顺序机制、失败后旧执行者如何被禁止继续，以及多节点/多身份和旧版本如何被覆盖。锁/lease 失效或网络断开不自动证明旧进程停止。持锁跨 OS 边界也不使数据库提交和 spawn 原子化；必须记录并处理 spawn 已发生但事务/响应不确定的窗口。
4. **证据分层**：至少区分受控启动意图已登记、实际 OS 启动已被受控执行者观察、持久启动事实已确认，以及最终终止/效果事实。OS 创建/恢复进程不等于成功运行任务、产生效果或完成。Windows 可能先创建 suspended child 再分配/恢复；各阶段失败/崩溃如何定性须针对选定 launcher 定义，不由 PID 或缺日志推定。
5. **未知不重派**：有意图后若不能证明是否已跨执行边界，保留原 launch identity/claim、预算和事实并阻止第二次启动；先停止或隔离可能仍运行的原执行者，再按受保护证据人工或受控对账。一次失联、进程列表中找不到 PID、重启后无本地记录、超时、仅凭失效 lease 均不单独证明未执行或未产生效果。不得据此退款、改 attempt 或推导 `no_effect`。
6. **收尾和新外部效果分开**：已可信启动且撤销/相关权威失联时，候选仅允许该执行内有界只读验证、结果登记及安全停止，不新增 push/merge/deploy 等效果；可登记的结果必须标明真实状态而非捏造 PASS。预算刚耗尽但授权仍有效不属于此分支：最后一次已准入任务的独立验证和合法交付正例仍须通过。对网络故障下哪些效果已获授权且仍能安全交付，须先解决上文 SC-RUN-006 边界及 WP4 效果协议。

## 最小事件矩阵（候选测试义务，非运行结果）

| 已知序列 | 必须验证的结果 |
|---|---|
| revoke 在实际启动栅栏前生效 | 原任务不新启动，不重消费；原 receipt 保留，既有有效恢复按合同处理 |
| 许可提交 → revoke 生效 → 尚未 spawn | 不能仅凭旧许可启动；验证实际 launcher/fence，而非仅 mock 返回值 |
| 启动栅栏先于 revoke 且实际执行已可信确认 | 同一执行可按撤销收尾边界停止和登记；不生成新根或新外部效果 |
| 原任务尚未启动 → 启动意图已登记 → spawn 结果或事实提交丢失 | 保持未知并封住第二次启动；存在进程和无进程只是不同观察，不自动推导效果或退款 |
| 后端返回错误、daemon 崩溃或系统重启 | 针对选定实现证明错误发生于何处；无法证明之前无启动时仍未知，不把通用 error 当 `not_started` |
| T 拒绝新 repair，最后一次 receipt 仍有效且当前授权可核 | 禁第七次新增准入，保留最后任务原正例：验证、独立评审与合法 PASS 交付；不把安全收尾限制套到仅预算耗尽 |
| T 查询故障，但其他控制/授权/效果权威的可用性不同 | 分别覆盖可验证原授权的允许正例和无权威时安全停止；先明确 SC-RUN-006 的逐动作合同，不用拒绝代替全部正例 |
| 同请求并发、启动前/后丢响应、daemon 重启、旧 writer 恢复 | 原 receipt、逻辑根及 launch identity 一致；真实执行不重复，旧 writer 不能绕过 fence；未知经确定性协议对账 |
| 启动后控制权丢失或 Windows Job 归属失败 | 观察持久结果与受控进程/后代状态；能力不足须阻止该可信路径或明确 HOLD，不能把告警当隔离保证 |

## 待决及验证门槛

- 确定 D1/D2 的独立身份、受保护启动代理、同一撤销排序权威、可恢复事实存储和独立防回退；覆盖所有生产启动路径及历史旧 writer，不能靠应用自报。
- 确定 OS spawn 前/后和 DB 提交的真实故障窗口、隔离与结束证据、启动错误分类、未知对账权限及保留期限；确保不会因等待未知而释放唯一槽再发第二次。
- 配对 SC-RUN-006 查询故障正例、D4 有界收尾与 WP4 的 effect/revoke 规则，确认哪些具体动作在何种当前授权证据下允许；保留第六次合法交付和签名 resume 正例。
- 先审查版本化夹具、专用隔离资源和安全清理，再以真实入口、受控并发与故障注入分别验证 Linux/Windows；模拟器/静态阅读不能代替身份隔离、进程树、DB、远端或断电证据。
