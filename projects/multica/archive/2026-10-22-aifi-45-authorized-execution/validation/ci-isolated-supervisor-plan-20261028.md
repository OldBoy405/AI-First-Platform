# AIFI-45 测试实例监督器：初步实施边界

本文件摘录独立设计会话 `01a182b5-83e4-7020-aecc-d1aa41ff1aaf` 的建议；**仅为计划，未实现、未验收，不解除现有 BLOCK**。

1. 新模式先分流，不触既存容器、不回退旧路径；固定引擎、端点、镜像和命令，不接受外部实例 ID、URL、模块路径或任意 adapter。
2. 拆出纯状态机；固定同步 controller 只调用可信 engine/probe/record。独立 supervisor 启动命令，通过有界、分帧、带序号的专用通道传数据，不接收 Promise 对象。
3. controller 与子进程双流并发读取、限额；原始诊断默认丢弃，仅输出白名单字段和枚举错误。超限、截断、解析失败均判失败，不凭部分 PASS 成功。
4. journal 需受保护 root、排他创建、完整写入、文件同步关闭、不可覆盖发布、目录持久化全部成功后才同步 ack；intent ack 前禁止 create。任一步失败保留现场并使后续过程失败。
5. 验证进程树隔离及退出：Linux 考察不可迁出的 cgroup；Windows 考察挂起启动、先入 Job 再恢复。缺相应能力须在 create 前拒绝；leader 退出不代表进程树为空。这是候选设计，不代表本机已有能力或用户已批准运行具体实现。
6. 树为空、journal 健康且重新核验归属后，仅对完整 ID 普通 stop/rm，再确认 ID、名称均缺席及 cleaned ack。非零退出可清理，但原失败不可清除。
7. 先用假凭据、fake I/O、无权限子进程覆盖 rejection/species、空异常、洪泛、短写、丢回执和后代残留；关键门禁逐项变异验证。

create 丢 ack 不重试、不按名称删；未知归属或退出状态保留。不得靠全局 rejection listener、有限替换或声称任意 Promise 可安全处理。此设计无法自动保证断电后的清理、跨平台持久性、恶意同权限代码、所有泄密通道或测试真实性；正式迁移与 CI 接线也未完成。原容器与保留库不在本次测试范围。
