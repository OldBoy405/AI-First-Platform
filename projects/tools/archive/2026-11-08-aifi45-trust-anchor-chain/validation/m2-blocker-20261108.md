# M2 闭环的真实阻断点（2026-11-08）

## 结论

**真实跨端闭环没有走通。阻断点不在 operation 白名单，也不在 T 侧实现，而在 M 的 daemon 启动门。**

证据：`e2-m2-real-loop-20261108/crctl-admission.stdout.txt`

```
ERR pipeline task preparation failed component=daemon task=9d8834db-…
error="EXECUTION_CONSUMPTION_REQUIRED: static contract checked; current head, revocation, claim and trusted consumption are not connected"
```

对应源码：`multica/server/internal/daemon/execution_verifier.go:62-68`

```go
// No receipt, activation or claimed identity is inferred from a static
// check. Do not start the agent until current-head/revocation/claim and
// the isolated control channel have been verified and consumed by T.
return errors.New("EXECUTION_CONSUMPTION_REQUIRED: static contract checked; current head, revocation, claim and trusted consumption are not connected")
```

## 为什么这不是缺陷，而是未完成

这段是**有意 fail-closed**：它拒绝在「T 侧尚未验证并消费」时启动 agent —— 这个方向是对的。
缺的是它**之后应有**的那段接线：daemon 在 trust root 装完 key/grant/source 之后，
应当去核对当前 head / 撤销 / claim，并通过受保护控制通道让 T 侧真实消费一次，
然后才放行；现在是**无条件返回错误**。

即设计 §实现落点里那两条还没落：

- `daemon/execution_trust.go` / `execution_verifier.go`：装配后应做「真实 crctl 检查 + 当前 head/撤销/claim」；
- `daemon/execution_binding_{relay,client,endpoint}.go` 与 task launcher：向控制入口传同一 trustRoot 与受保护通道。
