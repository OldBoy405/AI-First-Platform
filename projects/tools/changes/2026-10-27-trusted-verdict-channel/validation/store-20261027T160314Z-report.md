## 断言覆盖

`apply once 与原字节重放`：首帧 sequence=1/prev=null/command_digest=sha256(commandBytes)；同 request 原字节重放 `replayed=true` 且 **业务函数只执行一次**、返回原 result bytes、返回原 frame；同 request 换 command bytes → `EXECUTION_CONTROL_STORE_CONFLICT`；frame 发布前失败 → 0 帧、head 不前进、journal 停在 `prepared`；业务函数抛错 → 同样 0 帧 + `prepared`（证明「journal 先于业务」）。

`冻结帧链拒绝断链与占位签名`：跳号、`previous_digest` 未指向前一帧、`AA==` 占位签名、签名不足 64 bytes 全部 `EXECUTION_CONTROL_STORE_CORRUPT`；磁盘上三帧真实链可校验。

## 平台注记（不隐瞒）

Windows 无法对目录句柄 fsync（EPERM/EINVAL），模块对该错误仅在 `kind==='dir'` 时容忍并留注释；文件内容仍先 fsync 再 rename。POSIX 上目录 fsync 正常执行。此为已知耐久性差异，Gate 3 报告须如实列出。
