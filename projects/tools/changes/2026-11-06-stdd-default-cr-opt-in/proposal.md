# 工作区入口精简与 STDD／CR 流程隔离

## Why

知识库根 AGENTS.md 仍将 tools CR 设为默认入口并无条件要求读取整套 CR 资料， 与当前使用 STDD 的实际情况不一致；部分 CR 说明已落后于现行契约， 可能导致额外上下文开销、流程误路由、错误操作工作区或审批语义混淆。

## What Changes

- 精简知识库根 AGENTS.md：保留安全、数据完整性与工程底线，按任务和流程加载专项资料。
- 明确按变更选择流程：新开发默认 STDD，已有变更沿用原流程，只读问题不注册，归属不明时先确认。
- 修正根入口中的 CR 注册、审批、操作工作区、解析回退和固定计数等陈旧说明，引用现行权威契约而非复制路由表。
- 更新根 README.md、dir-graph.yaml 的相关说明，必要时只限定 CONTEXT.md 的适用范围；明确 STDD 三根、业务仓绑定及技能加载入口。
- 分离 ../tools/AGENTS.md 的工具包维护工程约束与执行 CR 的流程约束，不以使用 tools 能力等同于进入 CR。
- 仅修正全局 ~/.pi/agent/APPEND_SYSTEM.md 的优先级歧义：安全与数据完整性是底线，其内优先满足用户要求。

### New Capabilities

- **workflow-routing**：按变更身份、用户选择和目标项目绑定决定应加载的工作流；不执行状态映射、任务双写或审批互认。

### Modified Capabilities

- **prompt-governance**：常驻底线与流程资料分层，修正陈旧 CR 说明，保留数据、授权、工程规范与既有改动。

## Success Criteria

- [ ] 新开发未指定流程时入口明确选 STDD；用户显式选择 CR 时仍指向合法注册与流程入口。
- [ ] 已有 CR 沿用原合同，不因默认 STDD 被转换；流程切换须单独确认，不映射或伪造完成状态。
- [ ] 只读分析不自动注册 STDD 或 CR；归属、绑定或授权不明时不执行受控写入。
- [ ] STDD Gate 与 CR 审批不互认；流程确认不自动授权 Git 提交、推送或部署。
- [ ] 根入口不再无条件要求读取完整 CR 手册，并能说明 STDD 的实际绑定及按阶段读取路径。
- [ ] 陈旧的注册、审批、工作位置、回退和固定计数说明已修正，权威状态、参数和权限不在根入口复刻。
- [ ] 既有受控账本、发布基线、历史产物和用户未提交改动保持完整；全局文件仅修正已确认的优先级歧义。
- [ ] 提供可复核的静态检查与场景评审结果，并明确它们不证明运行时路由、实际部署或最终请求 token 占比。
