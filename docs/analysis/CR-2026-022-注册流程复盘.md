## 三、关键问题与决策记录

### 3.1 trunk 脏（附件未跟踪）

Skill 要求 trunk clean 才能注册，而附件（注册源文档）就在 trunk 未跟踪区。**决策**：附件随 register 提交一起入库——register 模板是白名单合法形态，附件是该 CR 源文档，顺带满足 clean 前置，一举两得。先例佐证：CR-2026-021 的 register 提交（6a9f180）即含完整 cr.md。

### 3.2 受控 shell 白名单适配（耗时大头）

`git commit -m "docs(analysis): ..."` 被 `FORBIDDEN_SUBCOMMAND` 拒绝。取证结论：白名单（`controlled-shell/rules.json`）的 commit 只放行 `wip:` / `[cr]` / `merge(` 三种前缀，或 register / task-breakdown / writeback 三种模板。历史先例（`docs(analysis)` / `docs:` 前缀）是白名单收紧前的提交，**当前形态不合法**，不能照抄。

### 3.3 summary/source 写入通道确认

`cr-init` 生成骨架（`summary: ""`、`source: manual`），而 `crctl backlog-set` 白名单只有 `prd-path|sdd-path`——SKILL Step 2.3 声称的写入通道**不存在**。取证：`git log`/`git show` 翻 CR-2026-021 的 register 提交，确认先例做法是"cr-init 建档后、register 提交前直接补全 cr.md 字段"（另有 `amend register` 先例证明注册记录是 living documents）。**决策**：跟随先例直接补字段。

### 3.4 commit 模板解析失败一次

`--template register` 要求 subject 含 `CR-\d{4}-\d{3}`（`resolveTemplateCr`：分支名探测 → subject 正则兜底 → fail-fast）。注册场景在 master 分支提交，分支探测必然落空，只能靠 subject 编号。**教训**：SKILL 示例 `-m title` 本身有误（见第五节缺陷 1）。

### 3.5 multica fetch SSL 失败（环境问题）

`git fetch origin` 报 SSL certificate verify failed（自签名证书链），不阻塞：worktree 从本地 main（= 最近 merge 的 CR-2026-012）派生成功。**建议**：一次性配置 `sslVerify` 或导入证书，避免每次 fetch 白等一轮。

## 四、耗时归因

| 耗时点 | 原因 | 性质 |
|---|---|---|
| 受控 shell 白名单适配 | commit 形态不在 SKILL 覆盖范围，需查源码 + rules.json 取证 | 一次性认知成本，修 SKILL 后归零 |
| summary/source 写入通道确认 | SKILL 声称的 backlog-set 通道不存在，需查先例定夺 | 漂移造成的查证成本 |
| commit 模板解析失败 1 次 | SKILL 示例 `-m title` 缺 CR 编号 | 纯试错成本，fail-fast 兜底 |
| multica fetch SSL 失败 | 本机证书/代理环境 | 环境问题，不阻塞 |
| trunk 脏处理 | 附件必须随注册入库 | 流程必需 |

**结论**：慢在"确认正确做法"（白名单形态、summary 写入先例、模板规则三处取证），不在执行动作（cr-init / commit / push / worktree 均秒级且一次成功，零返工）。

## 六、确定性化机制建议（三层）

对注册这一标准流程，"试错 + 查先例"不应是常态成本。确定性不靠"Agent 每次更小心"，靠三层机制：

| 层 | 机制 | 作用 |
|---|---|---|
| 1. SKILL 与实现对齐 | 按第五节缺陷清单重写 requirement-register 相关步骤 | 照抄即对，试错归零 |
| 2. lint 机械防线 | R6/R7 扩展：校验 SKILL 内 `crctl`/`git` 命令形态与 crctl.mjs / rules.json 一致 | 漂移在 lint 阶段被抓，不在执行时爆 |
| 3. crctl fail-fast | 白名单 + `resolveTemplateCr` BAD_ARGS 兜底 | 前两层失效也不产生错误产物 |

**理想态**：注册 = 机械 checklist（cr-init → 补字段 → add → commit register → push → worktree ×2 → 验证），每步命令确定、结果可预期；"查先例"仅在防线未覆盖的新场景才需要。
