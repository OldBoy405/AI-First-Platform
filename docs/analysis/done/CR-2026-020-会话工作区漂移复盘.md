## 二、根因分析

### 2.1 事实源错位：用主工作区 cr.md 判断 CR 进度（最大根因）

CR 生命周期内**全部产物与状态推进都发生在 worktree 分支**（`[cr] status ...` 提交链即真实进度），而主工作区 cr.md 的 status 停留在注册时值（drafting）。`crctl status` 默认读主工作区，输出的是**陈旧视图**。承接方只看了主工作区状态就动手，等于在不知道"分支上已到 developing"的情况下重写需求。

这是数据布局层面的固有陷阱：**同一 CR 的权威状态存在分支上，主工作区 cr.md 只是注册快照**，二者分叉无任何工具提示（reconcile 的投影对账在 PG 侧，Agent 工具层不可见）。

### 2.2 覆盖信号未读：Write 返回 edit 而非 create

覆盖前 Write 工具明确返回 `edit file success`（文件已存在）且 diff 为 79 行替换——"目标文件已存在"是硬信号，正确动作是停止并调查来源（git log 该文件）。承接方未读信号，直接覆盖，且未在覆盖前对比内容差异。

### 2.3 并行活动信号未查：git status 的未提交修改

worktree 里 `approval.yml` 有 crctl approve 写入的未提交修改（tech-design / development-start 段）——这是"有并行会话正在活动"的直接信号，`git -C <worktree> status --short` 一眼可见。承接方全程未查 worktree 的 git status / git log。

### 2.4 跨会话无强制恢复机制：resume-cr 存在但未成为入口

tools 包已有 `resume-cr` pipeline（trigger: resume，输出状态 + 产物 + 下一步），但没有任何 SKILL 或流程把它设为 CR 任务的**强制第 0 步**，各阶段 SKILL 的前置校验只查"文件存在/状态匹配"，不查"分支进度与主工作区视图是否一致"。承接方凭会话记忆（"我刚注册完，还是 drafting"）行动，记忆与真实状态必然随时间漂移。

## 四、改善方案（三层）

### 4.1 行为层：CR 写前四查（立即生效，已固化长期记忆）

任何 CR 写操作前，按序执行：

```text
① git -C .rayai-worktrees/{bucket}/requirement/{CR-ID} log --oneline -15
   → 读 [cr] status 提交链 = 真实进度（drafting→…→developing 全链一目了然）
② ls worktree 内 change-requests/{CR-ID}/ → 产物存在性（prd/sdd/plan/tasks/review-annotations/approval）
③ git -C worktree status --short → 未提交修改 = 并行会话活动信号
④ 写入时工具返回 edit/create、diff 替换规模 → 已存在则立即停止，调查来源后再写
```

### 4.2 tools 工具层（建议立项，一次投入长期受益）

| # | 改进 | 说明 | 量级 |
|---|---|---|---|
| R1 | **resume-cr 提升为强制入口** | 各阶段 SKILL（write-requirement-prd / write-tech-design / write-dev-tasks / implement-code）Step 1 强制"先跑 resume-cr 或等价进度快照"，从可选变必选；输出状态链 + 产物清单 + 下一步 | 小（SKILL 文档修订） |
| R2 | **crctl status 增加分支视图**（或新子命令 `crctl progress`） | 一次输出：worktree 分支 `[cr] status` 提交链 + 产物存在性 + **主工作区/分支状态分叉警告（STATUS_DIVERGED）**。Agent 一条命令拿全事实，不再手工翻 git log | 中（crctl.mjs 扩展） |
| R3 | **注册时登记分支指针** | `_backlog.yml` 条目加 `worktree-branch` 字段（requirement-register 写入），crctl status 直接读它定位权威工作区，消除"哪个工作区是事实源"的歧义 | 小（register + 读取两处） |
| R4 | **SKILL 覆盖防护升级** | write-requirement-prd / write-tech-design 把"prd.md/sdd.md 已存在"从错误处理表提升为 Step 1 硬校验：存在即 abort，输出"该 CR 已有产物，请先 resume-cr 确认进度"，禁止静默进入编辑模式 | 小（SKILL 文档修订） |

- 长期记忆已固化："CR 工作必须以 worktree 分支为事实源，写前四查"（development_practice_specification），后续会话自动生效。
