# 评审 run 可靠性最小方案（重试熔断 + 无产出看门狗）

## 1. 背景与目标

CR-2026-059 代码评审阶段，reviewer run 因在**确定性错误**（`SHELL_UNAVAILABLE`，本机 git 为 deny-closed 白名单网关）上连续重试 279 次而长时间空耗；此前同阶段还出现读文件 ENOENT 后 >4h 静默退出。二者共同根因是：**重试逻辑不区分「瞬时错误」与「确定性错误」，对后者无界重试。**

本方案目标单一：让 run 在命中确定性错误时**立即停止并上报**，而不是无限循环。不做委派前费用预检（已拍板不做），不做其他可靠性改造。

## 2. 问题定位

重试判定只发生在**一个点**：run 失败后「是否重试」的判定分支。现有行为对该分支一律重试（或有界重试但阈值过高）。修复只需在该分支前插入一次错误码分类，不动其余链路。

## 3. 最小方案：错误码分类 + 熔断规则

### 3.1 分类规则

| 类别 | 判定 | 处置 |
|---|---|---|
| **确定性错误** | 错误码命中「确定性错误码集合」 | 不重试，立即按现有 `TECHNICAL_ABORT` / `agent_error` 路径终止并上报 |
| **瞬时错误** | 网络超时、5xx、限流等未命中集合者 | 维持现有重试策略不变 |

### 3.2 确定性错误码集合（初始值，可扩展）

```text
FORBIDDEN_SUBCOMMAND
FORBIDDEN_FLAG
FORBIDDEN_*
SHELL_UNAVAILABLE
SCHEMA_INVALID
TASK_ISSUE_REQUIRED
ILLEGAL_LEDGER_STATE
PAYLOAD_NOT_FOUND
```

> 说明：`FORBIDDEN_*` 用前缀匹配；其余为精确匹配。集合放配置/常量，不散落硬编码。

### 3.3 熔断规则

- 命中确定性错误 → **0 次重试**，立即终止并保留原始错误码上报。
- 未命中 → 现状不变（不再另加阈值，避免与既有重试策略冲突）。

## 4. 改动点（最小入侵）

只改一处：**重试判定入口，插入 `isDeterministicError(code)` 判定。**

- 新增：一个 `isDeterministicError(code)` 函数 + 一个错误码集合常量（或配置项）。
- 修改：重试循环的判定条件，从「一律重试」变为「非确定性错误才重试」。
- **不动**：错误上报路径、`TECHNICAL_ABORT` 流程、Provider 层、任务终态、账本写入——全部复用现有机制。

伪代码（示意，落到实际语言时对齐现有错误码表示）：

```text
on_run_failure(error):
    if isDeterministicError(error.code):
        report(error)          # 复用现有 final-failure 上报
        return                 # 不重试
    else:
        retry_or_fail(error)   # 现有策略原样
```

## 5. 刻意不做（YAGNI）

- 不引入熔断器状态机（half-open/closed 等）——这是「请求级熔断」，不是「服务级熔断」，一次判定足够。
- 不做可配置重试次数面板——瞬时错误沿用既有策略，无需新阈值。
- 不做委派前费用预检（已拍板）。
- 不新增持久化/账本记录——熔断是运行期行为，不落 CR 账本。
- 不改 system prompt（确定性错误禁止重试已由本方案在 runtime 层承担，prompt 无需重复）。

## 6. 验收标准

1. 构造一个返回 `SHELL_UNAVAILABLE`（或任一确定性错误码）的 run → 断言**无重试**、立即终止、上报含原始错误码。
2. 构造一个网络超时（瞬时）→ 断言仍按既有策略重试，行为与改动前一致。
3. 现有四类评审正常路径回归通过（`review-record` 落盘不受影响）。

## 7. 无产出看门狗（防静默挂死）

### 7.1 问题

第 1 次阻塞是「无错误码的无声死亡」：run 长时间无产出，既不失败也不结束。熔断按错误码触发，抓不到无错误码的场景；prompt「失败必须出声」只兜「结束前出声」这一半，兜不住「run 挂死不退出」这一半。本节的看门狗补另一半。

### 7.2 最小方案：流式空闲计时器

在 run 执行器加一个**空闲计时器**，只在「完全空闲」时倒计时：

- 距上次任何事件（token 流 / 工具调用 / 系统事件）超过 **N 分钟** → 终止 run，标记 `no_output_timeout`，走**既有** final-failure 上报路径。
- 有 token 流或工具调用即重置计时器，不误杀正常长读。
- 默认 **N = 20**（保守值）：评审 run 正常的只读取证或命令等待在数分钟内，20 分钟完全无事件几乎必然是死或失控。

### 7.3 改动点（最小入侵）

- 新增：一个空闲计时器（复用既有 run 事件流，不新开进程）。
- 修改：run 执行器事件循环，每收到事件重置计时器；计时器到点走既有终止/上报分支。
- **不动**：上报路径、final-failure 语义、账本写入、Prompt 层——全部复用现有机制。

### 7.4 与熔断的分工（互补，非二选一）

| 防线 | 兜什么 | 触发条件 |
|---|---|---|
| 重试熔断 | 有错误码的确定性失败 | 错误码命中集合 |
| 无产出看门狗 | 无错误码的挂死/空转 | 超时无任何事件 |
| prompt「失败必须出声」 | 正常结束但空回复 | 模型遵守约束 |

### 7.5 边界说明

- 看门狗只覆盖「run 不结束」；若 run 已正常结束但回复为空，看门狗不触发，靠 prompt 兜底。
- N 值若误杀真实长任务可上调，但不应大于 30 分钟（超过即失去「及时止损」意义）。

## 8. 边界说明（诚实）

- 本方案**不覆盖** provider 账单 403（`insufficient_user_quota`）：它是确定性错误，但发生在 Provider 调用层，未必进入本重试判定分支；若其错误码也流经该判定点，可将其加入集合获得「同错误码不再重试」的收敛，但收益有限（本质仍靠充值）。此风险已显式接受。
- 静默退出（无错误码的无声死亡，如 ENOENT 后空输出）分两种：run 挂死不退出 → 由 §7 无产出看门狗兜底；run 已结束但空回复 → 由 quality-reviewer-agent system prompt 的「失败必须出声」约束兜底。二者互补，均在本方案内。
